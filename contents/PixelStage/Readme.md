# PixelStage
### Design the frame. Own the moment.

## TL;DR Version
**PixelStage** is a robust, browser-based design tool built to save you time. It turns standard screenshots into professional isometric mockups instantly, eliminating the need for heavy design software.

You simply paste a URL or upload an image, select a device frame (like an iPhone or Mac), and use intuitive sliders to rotate the view in 3D space. It features auto-saving, API-driven screenshot fetching, and high-res export via Canvas rendering. It exists because I wanted to make my portfolio look elite without the manual grind!

## Introduction (The Lazy Developer's Manifesto)
Let's be honest for a second: Sometimes I am just lazy. Or rather, I am *selectively* productive. I realized I was spending hours manually creating mockups for my page designs - tweaking shadows, aligning device frames, and adjusting gradients. It drove me crazy. I could have been using that time to design new pages, code new features, or literally do anything else.

But instead, I was stuck in a loop of repetitive pixel-pushing. So, in a moment of clarity (and refusal to do boring work), I leaned into the DRY principle (Don't Repeat Yourself) and built **PixelStage**. If I have to do something more than twice, I'm writing a script for it. This project is the result of me wanting to get back to the fun stuff while still producing gorgeous visual assets.

## Project Overview
PixelStage is born from a simple frustration: the friction between finishing a project and presenting it. We spend hours coding, but often fail at the finish line because presenting the work feels like a whole new chore. I built this tool because I was tired of that chore. Call me efficient, or admit that sometimes I am just lazy, but I believe that if a machine can do it, a human shouldn't have to.

It represents the power of automation in design. By running entirely in the browser, PixelStage proves that you don't need native apps to perform complex visual tasks. It allows me - and now you - to generate high-quality assets in seconds.

The moment that sparked this was when I looked at my to-do list and saw "Create screenshots for landing page." I sighed, closed my laptop, and decided that instead of doing that task, I would spend the next week building a tool to do it for me forever. That is the definition of developer virtues: working hard once so you never have to work hard at that specific thing again.

## Instructions (Mastering the Stage)
1.  **Choose Your Source:** Navigate to the Content tab. Either paste a website URL to fetch a live screenshot (via API) or click the upload area to drop in your own image.
2.  **Select a Frame:** Go to the Canvas tab and pick a device: iPhone, Mac, Browser, or None. Adjust the Corner Radius and Shape to match your style.
3.  **Go 3D:** Use the 3D Transform sliders to rotate the canvas. Tweak Rotate X and Rotate Y for that trendy isometric look. Adjust Perspective to change the intensity of the 3D effect.
4.  **Style the Scene:** Open the Background tab to choose a preset gradient or pick a solid color. Use the Shadow tab to add depth to your floating device.
5.  **Export:** Hit the Export tab. Select your resolution (up to 4x) and click Download PNG, or just hit Copy to Clipboard to paste it directly into your socials.

### Theory (The Math Behind the Magic)
The concept behind PixelStage is deeply rooted in the philosophy of Automation and the evolution of digital presentation. We shifted from Skeuomorphism to Flat Design, and are now in an era of Skeuominimalism, where depth and perspective (the Z-axis) provide hierarchy.

However, the driving force here is the DRY Principle applied to design workflows. The mathematical foundation utilizes Affine Transformations in Euclidean space, handled seamlessly by **[CSS 3D Transforms](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Transforms/Using_CSS_transforms)**. By manipulating `rotateX`, `rotateY`, and `perspective`, we simulate a camera moving around an object, automating the perspective drawing techniques that artists have used since the Renaissance.

This tool empowers the creator to produce assets that align with high visual standards without the manual effort. It leverages the No-Code ethos, where complex visual outputs are generated via simple slider inputs and state management.

### Challenges (The Dragons Faced)
*   **CORS & Exporting Tainted Canvases:** One of the biggest hurdles was allowing users to export images that contained content from external URLs. Browsers aggressively block canvas exports if "tainted" images are drawn on them due to security protocols.
*   **3D Coordinate Mapping:** Translating 2D slider inputs (0-100) into meaningful 3D CSS rotation values (degrees) while maintaining a center of origin that feels natural to the user was mathematically tricky.
*   **Iframe vs. Image Handling:** Managing the logic to switch between a live `<iframe>` preview (which cannot be easily exported to an image) and a static screenshot image for the final export required a delicate balancing act.

### Solutions (The Spells Cast)
*   **Proxy Integration:** Implemented logic to route external images through CORS-friendly APIs like **[Microlink](https://microlink.io/)** or **[ScreenshotAPI](https://screenshotapi.net/)**, ensuring `crossOrigin="anonymous"` attributes were set properly on instantiated objects.
*   **Transform Origin Magic:** Carefully tuned the CSS `transform-origin: center center` and exposed a dynamic `perspective` slider. The code calculates translation values to keep the object perfectly centered even during extreme rotations.
*   **Hybrid Rendering Engine:** Created a smart toggle system. The app uses an iframe for "Live Preview" interactivity but silently switches to an API-fetched screenshot or **[html2canvas](https://html2canvas.hertzen.com/)** render logic when the user hits the Export button.

### Impact
PixelStage significantly reduces the "Time to Share" for digital creators. Instead of context-switching to heavy desktop apps, a developer can generate a marketing asset in under 60 seconds directly from their browser. This improved workflow leads to more frequent sharing of work, better documentation visuals, and a higher standard of presentation across the indie web community.

### Scope
The project focuses strictly on **presentation framing**. It includes features for device wrapping, 3D rotating, and background styling. It intentionally avoids being a full-featured image editor - there are no cropping tools, brush tools, or complex layer blending modes. The boundaries are defined by "what makes a screenshot look good quickly," excluding bloated features to keep the interface lightning fast.

## Technical Details
The core of PixelStage acts as a reactive state machine. A central `state` object holds every variable - from the background color hex code to the Z-axis rotation degree. The application uses vanilla JavaScript to listen for input events, update this state, and then trigger an `updateCanvas()` render loop. This loop applies the state values to the DOM using CSS Custom Properties and direct style manipulation, ensuring butter-smooth 60fps performance for the 3D transformations.

### Technologies
This project leverages the power of pure web standards to cast its spells!
*   **[CSS3](https://developer.mozilla.org/en-US/docs/Web/CSS)**: Specifically the 3D Transform module to handle the visual heavy lifting, offloading the rendering to the GPU for smooth interaction.
*   **[Canvas API](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API)**: Used purely for the generation of the final export file, flattening the 3D DOM structure into a single raster image.
*   **[LocalStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)**: Provides the persistence layer, saving the user's workspace automatically so they never lose a brilliant configuration.

### Future Improvements

### Known Bugs
*   Direct export of a live `<iframe>` is blocked by browser security policies; the tool currently falls back to a placeholder or requires a Screenshot API fetch for these cases.
*   The 3D rotation sliders can occasionally be finicky on very small mobile touch screens due to the density of the UI controls.
